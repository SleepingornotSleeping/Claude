# 英文字幕 → 微信公众号中文文稿

## 概述

这是一个完整的编译工作流：将英文视频/播客字幕翻译并整理为可直接用于微信公众号发布的中文长文。最终输出为 `.docx` 文件。

**核心原则**：这不是逐句翻译，而是"编译"——翻译 + 编辑 + 重组。目标是让中国读者读起来流畅自然，像是一篇原生的中文深度文章。

---

## 完整工作流（按顺序执行）

### 第一步：理解素材

1. 读取用户上传的字幕文件（从 `/mnt/user-data/uploads/` 获取，或用户直接提供的路径）
2. 通读全文，理解核心内容、说话人、话题结构
3. 识别素材类型：访谈对话（Q&A）、演讲独白、圆桌讨论等
4. 记录关键信息：人名、公司名、数据、时间点

### 第二步：搜索背景信息

用 `WebSearch` 搜索与内容相关的最新背景信息，比如：

- 涉及的公司最新融资、估值、营收数据
- 说话人的身份、职位、近期动态
- 提到的行业事件或政策的最新进展

**目的**：补充字幕中没有的上下文，同时为后续事实核查做准备。

### 第三步：翻译与改写

将英文内容翻译为中文书面语。这是整个工作流最核心的步骤。

#### 翻译原则

- **书面语，不是口语**。去掉所有口头禅（you know, like, I mean, right, so）、重复、碎片化表达、语气词填充
- **自然的中文表达**。不要翻译腔。如果一句话直译不通顺，就用中文的方式重新表达同样的意思
- **保留专业术语的英文原文**。在首次出现时用"中文翻译（English Original）"格式，之后可只用中文。例：\u201c扩展定律（scaling law）\u201d。常用术语如 AI、RL、API、GPU 等无需翻译
- **数字用阿拉伯数字**。金额用"XX亿美元"格式
- **中文引号用全角引号\u201c\u201d**（U+201C / U+201D），不要用半角引号
- **人名保留英文**，除非有广泛使用的中文译名
- **长段落要拆分**。口语中一个人可能连续说很长一段，翻译时应根据话题转换拆成多个自然段
- **压缩冗余内容**。口语访谈中常有大量重复和绕弯，书面版应精简到核心观点，同时保留关键论据和有说服力的原话

#### 对话体（Q&A）的特殊处理

- 保留对话结构，每段发言前标注说话人姓名加冒号（如\u201cDwarkesh：\u201d\u201cDario：\u201d），说话人姓名**加粗**
- 提问者的问题也要整理为书面语，不能保留口语的散漫
- 回答中如果涉及多个话题，应拆成多个自然段

### 第四步：结构化组织

#### 文章标题

- 写一个信息量大、能引起点击欲望的中文标题
- 标题应包含关键数据或判断，不要笼统空泛
- 好的例子：\u201cARR 140亿美元，新融300亿美元，Anthropic CEO说AI行业2030年将是万亿美元生意\u201d
- 坏的例子：\u201cAnthropic CEO最新深度访谈\u201d

#### 开头导读/推荐语（放在正文之前）

- 2-4段简短的编者按，为读者提供阅读这篇文章的理由和上下文
- 包含：这是谁、为什么值得看、核心判断是什么、最新的背景信息（如融资数据）
- 语气：专业但不枯燥，让读者觉得\u201c这篇值得花时间读\u201d

#### 要点摘录（放在导读之后、正文之前）

- 根据内容价值提炼 5-25 条核心要点，编号列表。内容信息密度高就多提炼，信息量不大就少提炼
- 每条一两句话，概括一个独立观点或判断
- 作用：让没时间读全文的读者快速获取信息，也帮助全文读者建立框架

#### 章节划分（用于正文）

- 根据话题将正文分为若干章节（通常 8-15 个）
- 每个章节写一个简洁的中文标题，如\u201c一、技术指数增长与\u2018大计算块假说\u2019\u201d
- 章节标题应概括该部分的核心话题，帮助读者跳读

### 第五步：事实核查与修正

利用第二步搜索到的背景信息，对文章中的关键事实进行核查：

- 公司名称、人名、职位是否正确
- 融资金额、营收数据、时间点是否与公开信息一致
- 技术术语的翻译是否准确

如果发现字幕中的信息有误或过时，在译文中直接修正，无需特别标注。

### 第六步：生成图表（如适用）

审视文章内容，判断是否有适合用图表呈现的信息，比如：

- 营收增长数据 → 折线图或柱状图
- 时间线/里程碑 → 时间轴图
- 对比数据 → 表格
- 概念关系 → 简单示意图
- 流程/决策逻辑 → 流程图
- 因果链条/递进关系 → 流程图或阶梯图

如果有合适的内容，用 Python（matplotlib）生成图表，保存为 PNG 文件供 docx 嵌入。图表文字使用中文。如果内容不适合图表，跳过此步。

### 第七步：生成 docx 文档

使用 `python-docx` 生成格式规范的 Word 文档。运行项目中的辅助脚本：

```bash
python3 scripts/subtitle_to_wechat/generate_docx.py content.json output.docx
```

#### 内容 JSON 格式

在生成 docx 前，先将所有翻译好的内容写入一个 JSON 文件（`content.json`），结构如下：

```json
{
  "title": "文章标题",
  "intro_paragraphs": [
    "导读第一段...",
    "导读第二段..."
  ],
  "key_points": [
    "要点1...",
    "要点2..."
  ],
  "sections": [
    {
      "title": "一、章节标题",
      "paragraphs": [
        {
          "type": "normal",
          "text": "正文段落..."
        },
        {
          "type": "speaker",
          "speaker": "Dario",
          "text": "说话人发言内容..."
        },
        {
          "type": "highlight_strong",
          "text": "特别重要的观点（蓝色加粗）..."
        },
        {
          "type": "highlight_light",
          "text": "次要重要的观点（蓝色不加粗）..."
        }
      ]
    }
  ],
  "charts": [
    {
      "path": "chart1.png",
      "caption": "图表标题"
    }
  ]
}
```

#### 排版规范（已内置于 generate_docx.py）

- 页面：A4，页边距上下左右各 1 英寸
- 正文字体：Microsoft YaHei（微软雅黑），11pt
- 主色调：蓝色系（"2B579A" 深蓝为主色）
- 文章大标题：18pt，居中，深蓝色加粗
- 章节标题（H2）：14pt，加粗，蓝色
- 行距：1.5倍
- 段间距：after 200
- 说话人姓名：加粗，蓝色
- 要点摘录：编号列表
- 章节之间用蓝色分隔线隔开
- 导读区域用灰色小字与正文区分
- 特别重要观点：蓝色加粗
- 次要重要观点：蓝色不加粗
- 全角引号\u201c\u201d

### 第八步：推送到飞书

文档生成完成后，自动通过飞书机器人 Webhook 将文章摘要推送到飞书群。

```bash
python3 scripts/subtitle_to_wechat/feishu_notify.py content.json
```

Webhook 地址：`https://open.feishu.cn/open-apis/bot/v2/hook/a91e9058-32c8-4232-91b8-5620af17aa87`

推送内容：文章标题（加粗）+ 前5条要点摘录 + 提示语。

如果网络不可用（推送失败），不要中断流程，正常交付 docx 文件，并告知用户飞书推送未成功。

## 长内容处理策略

长访谈字幕（如 3 小时播客）可能有数万词。处理策略：

1. **不要试图一次性翻译全文**。先通读理解结构，再分章节翻译
2. **先写 JSON 内容，再生成 docx**。用内容 JSON 驱动文档生成，避免引号转义问题
3. **翻译时大胆精简**。口语中 50% 以上的内容是冗余的（重复、举例过多、离题），书面版应精简到核心

## 常见问题处理

| 用户反馈 | 处理方式 |
|---------|---------|
| \u201c翻译太绕了/太翻译腔\u201d | 回到那段内容，用纯中文思维重新表达 |
| \u201c太长了\u201d | 进一步压缩冗余，保留关键数据和核心判断；可建议拆分上下篇 |
| \u201c某个翻译不对\u201d | 搜索确认正确翻译，修正并更新文档 |
| 对话体 vs 文章体 | 默认保留对话体（Q&A），如用户要求改为文章体则重组为按主题叙述 |

## 输出清单

最终交付给用户的应包含：

1. 一个 `.docx` 文件，包含完整文章（标题 + 导读 + 要点 + 正文 + 图表）
2. 如有图表，图表已嵌入 docx 中
3. 飞书群推送：文章摘要已自动发送到飞书群（如网络可用）
4. 文件命名建议：`[主题关键词]_公众号文稿.docx`
